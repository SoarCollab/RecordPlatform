# 平台控制面运维

平台控制面提供租户生命周期、租户用户元数据、配额和少量安全配置的管理，使用独立平台身份及操作审计。

## 启用平台身份

执行增量迁移 `V1.23.0`，再按[平台管理员初始化](../../en/deployment/platform-administrator-bootstrap.md)创建平台管理员。初始化完成后保持一次性 bootstrap 关闭，通过 `PLATFORM_IDENTITY_ENABLED=true` 明确启用平台登录。启用开关不会提升已有租户管理员的权限。

迁移保留既有配置 ID，并将 `sys_audit_config.id` 从 INT 扩为 BIGINT，使缺失的安全配置能以应用生成的 Snowflake ID 重建。数据库自动分配 ID 仍保持禁用；启用新配置写入前必须完成此前向迁移。

所有平台请求使用：

```http
Authorization: Bearer <platform-token>
X-Tenant-ID: 0
```

令牌必须具有唯一角色 `platform_admin`、`scope=platform` 和身份租户 `0`。服务端从该身份派生固定权限；租户权限定义与角色映射不能授予保留的 `platform:` 权限。历史租户 `0` 的普通管理员仍保持租户身份。

通过 `GET /api/v1/platform/session` 读取平台身份和固定权限。目标租户使用 API 返回的外部实体 ID，目标用户使用外部用户 ID。不得将目标租户填入身份请求头；原始数字 ID 或错误类型的外部 ID 会被拒绝。

全部接口见 [API 索引](../api/index.md)。平台接口不提供模拟登录、文件内容和下载、原始 Nacos/环境配置、凭据、容器控制或硬删除。

## 创建并管理租户

1. 调用 `POST /api/v1/platform/tenants`，为本次操作生成新的 UUID `Idempotency-Key`，提供原因、不可变的小写 `code` 和显示名称 `name`。编码长 2–64 个字符、以字母开头，仅包含小写字母、数字和连字符。可选 `maxStorageBytes`、`maxFileCount` 留空时沿用现有配额默认值。
2. 保存结果中的 `resourceId`，它就是租户 ID。创建租户和初始配额在同一事务提交，不生成账号或默认密码。
3. 调用 `POST /api/v1/platform/tenants/{tenantId}/invitations`，使用另一个操作键，提供 `email`、`role: "admin"`、`expiresInHours`（1–168）和 `reason`，邀请首位管理员。一次性凭据通过现有邮件流程送达，API 和操作日志均不返回它。
4. 通过该租户的用户接口管理成员，保留最后一位有效管理员保护及自操作限制。平台管理员账号不出现在租户成员搜索中，也不能成为成员命令的操作目标。
5. 修改租户元数据或状态前，读取当前 `version` 并作为 `expectedVersion` 提交。租户状态变更会使旧授权状态和活跃租户会话失效；系统租户 `0` 不能被停用。

分页参数要求 `pageNum >= 1`、`pageSize` 为 1–100，关键字最多 100 字符。用户响应只返回允许的账号元数据，不包含密码哈希、授权版本、验证状态或文件路径。

## 配额与安全配置

修改配额前先读取目标租户配额。响应包括有效限额、当前用量、策略来源、执行模式和覆盖版本。新租户初始覆盖版本为 `0`；缺少覆盖时也返回 `0`，首次更新后版本为 `1`。限额必须为不超过 `9007199254740991` 的非负整数，更新后仍沿用既有配额灰度及 `SHADOW`/`ENFORCE` 策略。

全局配置注册表仅允许以下整数配置：

| 配置键 | 最小值 | 最大值 |
|---|---:|---:|
| `HIGH_FREQ_THRESHOLD` | 1 | 1,000,000 |
| `FAILED_LOGIN_THRESHOLD` | 1 | 10,000 |
| `ERROR_RATE_THRESHOLD` | 1 | 100 |
| `LOG_RETENTION_DAYS` | 1 | 3,650 |

配置响应明确标识全局数据库来源、能否在线修改、是否需要重启及当前版本。存储值损坏时返回 `value: null`、`state: UNAVAILABLE`，不会回显损坏的原始文本。操作者可读取版本后，在规定范围内提交新的修正操作。

`PUT /api/v1/system/audit/configs` 已停用并始终拒绝写入，包括历史租户 0 管理员。对应 GET 仍向有权读取租户审计的用户返回已校验的安全数值投影。配置写入统一使用 `PUT /api/v1/platform/configuration/{key}`，附带原因、操作键和预期版本。

## 重试与冲突处理

每次写入都必须提供规范 UUID `Idempotency-Key` 和最多 255 字符的非空原因。一个逻辑命令使用一个键，结果确定前保留原键及完整原始请求。

| 结果 | 客户端处理 |
|---|---|
| 成功 | 保存 `operationId`、`resourceId` 及返回的 `version` |
| 响应丢失或传输结果不确定 | 用原键和完全相同的载荷重试 |
| `50022 PLATFORM_VERSION_CONFLICT` | 重新读取并核对资源；重新确认的操作使用新键 |
| `50023 PLATFORM_IDEMPOTENCY_CONFLICT` | 该键已对应另一份请求，不得悄悄替换其含义 |
| `50024 PLATFORM_OPERATION_IN_PROGRESS` | 保留原键，不得给相同操作换新键绕过处理状态 |
| 已记录的终态失败 | 原键仍重放该失败；修正后的新逻辑操作使用新键 |
| 缺少 `Idempotency-Key` | HTTP 400、`10004 PARAM_NOT_COMPLETE`，补齐键后再发起命令 |

认证与授权拒绝沿用现有 401/403 边界。其他已校验业务错误继续使用项目的 `Result.code` 契约，不能仅凭 HTTP 200 判断写入成功。

操作领取记录先在独立短事务中持久化，业务变更与成功审计在同一事务提交；业务回滚后，再用独立事务记录脱敏失败结果。审计存储失败不会变成成功响应。

## 审计与中断恢复

`GET /api/v1/platform/audit` 和 `GET /api/v1/platform/audit/{operationId}` 要求平台审计权限。平台写入历史保存在系统专属的 `platform_operation_log`，不重复写入普通租户操作日志或成员日志。原因和变更摘要会限长、脱敏，失败只记录稳定错误码，不存储任意异常文本或原始请求体。

进程中断可能留下持久化 `PROCESSING` 记录。系统不会自动回收此类记录，也不提供强制成功入口。操作者必须先确认原进程不再执行，核查操作记录与当前资源状态，关联邀请投递或会话失效情况，再决定单独复核的恢复动作。保留原领取记录及诊断证据，不得为了让重试成功而删除记录、改写指纹或直接修改状态。

回滚必须使用经过复核、仍保留旧全局配置写入口禁用及安全只读投影的回滚构建。未修改的前一版本会重新向租户管理员和监控员开放 `PUT /api/v1/system/audit/configs`，不能直接作为回滚目标。紧急回滚若依赖入口层阻断，恢复流量前必须验证所有可达后端路径都拒绝该精确写入口，并确保配置读取仍使用安全投影。保留增量 schema、既有租户、配额、配置和平台操作历史，不回退迁移历史，也不重复执行一次性 bootstrap。

## 度量与验证

总览提供真实查询到的租户和账号元数据统计。租户用量中的业务审计与已完成存证批次统计只属于明确目标租户。共享健康信息仅返回 `database`、`redis`、`blockchain`、`storage` 的状态；缺失或失败的度量保持未知或返回请求失败，不伪装为 0 或健康。

Required CI 必须真实执行 MySQL/Redis 平台套件 20 例和增量迁移套件 2 例，均要求零跳过、零失败、零错误。单元及 HTTP 检查覆盖全部 24 个平台路由，以及角色、权限、类型化 ID、版本、日志和安全配置边界。本地没有 Docker 时不能宣称取得真实数据库验收证据。
